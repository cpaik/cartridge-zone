    Upload a game

    Already building with the OpenAI API? Bring the game here unchanged. Calls to /v1/chat/completions are answered by the model on each player's own GPU. No API key, no server bill.

    Uploaded games are saved in this browser. To share one, send the .html file; it runs for anyone who uploads it here.

    How games talk to the model

    Inside Cartridge Zone, these work exactly like the OpenAI API, answered by the model on the player's own device:

    • POST /v1/chat/completions with messages, temperature, max_tokens, stop, seed
    • stream: true server-sent events, like the real API
    • response_format: {type: "json_object", schema} for structured output
    • GET /v1/models lists the runtimes

    Plain fetch

    const res = await fetch("/v1/chat/completions", {
  method: "POST",
  body: JSON.stringify({
    messages: [{role: "user", content: "Hello!"}],
    max_tokens: 80
  })
});
const reply = (await res.json()).choices[0].message.content;

    The official OpenAI SDK

    import OpenAI from "https://esm.sh/openai";
const ai = new OpenAI({ baseURL: "https://cartridge.local/v1",
  apiKey: "local", dangerouslyAllowBrowser: true });
const r = await ai.chat.completions.create({
  model: "pocket", messages: [{role: "user", content: "Hi"}] });

    The built-in helper

    const line = await cartridge.chat(messages, {max_tokens: 60});
for await (const t of cartridge.stream(messages)) out.textContent += t;

    House rules

    • Games run sealed off: no network, no cookies, no access to this site. Only the model and public script CDNs (jsDelivr, unpkg, esm.sh, cdnjs) are reachable, so a game can't send players' words anywhere.
    • Inline your images and sounds as data URLs.
    • Replies are capped at 1,024 tokens, and one request runs at a time.
    • Small models are great at short in-character lines and bad at keeping score. Keep numbers in your own code.
